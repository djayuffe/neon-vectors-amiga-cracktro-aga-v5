# Low-level audit — 2026-10-01

## Result

The verified cracktro path is retained and hardened. Static source/assets validation and deterministic asset reproduction pass. Full assembly/Hunk execution validation could not be rerun in this environment because `vasmm68k_mot` and `machine68k` are unavailable; the test suite now reports those as explicit skips.

## P0 fixes

1. **Disconnected invalid experimental renderer calls from `DrawWire`.** The Phase 2C–4 routines had been called from the production frame loop even though their ABI/data model was incomplete.
2. **Prevented regression in `tools/validate.py`.** The validator now fails if the incomplete `UpdateShading`, octa/sphere/particle/sort, or `DrawSolid` calls are reintroduced into `DrawWire` without first replacing the guard as part of a real renderer implementation.
3. **Replaced false-positive comprehensive testing.** `COMPREHENSIVE_TEST.sh` now preserves command exit status, distinguishes PASS/FAIL/SKIP, performs real build/Hunk checks only when VASM exists, and performs the execution harness only when `machine68k` exists.

## P1 findings corrected/documented

- The active display is **4 bitplanes / 16 colours**, not the stale 3-plane description in parts of the docs.
- Screen storage is six plane-sized buffers because displayed planes 1 and 3 are double-buffered.
- The verified star count is `NSTARS=48`, not the stale README claim of 64.
- Historical Phase documents are now explicitly marked experimental and point to `docs/EXPERIMENTAL_3D.md`.
- `SCREEN_LONGS` comment no longer falsely describes six displayed planes / 64 colours.

## Experimental 3D defects found

- `cube_faces`: 8-byte records, but experimental walkers advance 10 bytes.
- `octahedron_faces`: 7-byte records, but experimental walker advances 10 bytes.
- `DrawSolid` prepares `d2..d5` while `BlitLine` requires `d0..d3`.
- `DrawSolid` relies on line-mode shared blitter registers before the production path initializes them.
- Claimed palette indices 24–31 require at least five bitplanes, but the display is four planes.
- “Gouraud” code is per-face flat lighting, not per-vertex Gouraud interpolation.
- Sphere workspace is zero-filled and has no geometry generator in the shipping path.
- Particles have no production initializer/renderer; `SortFaces` is a no-op.

These routines remain as reference material but are not executed by the shipping frame loop.
